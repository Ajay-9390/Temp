# NBA Program Management — Integration Guide

Audience: the other NBA platform teams (Courses, Outcomes, CO-PO-PSO, Assessment,
Attainment, CQI, Evidence, SAR, AI/RAG, Surveys, Auth/RBAC).

This module owns the **academic + accreditation context** and exposes stable UUID
identifiers and REST contracts you can depend on. It does **not** own Users/Roles/Permissions
(Auth/RBAC team) and contains no outcome/attainment logic.

- Base URL: `/api/v1`
- Swagger UI (dev): `http://localhost:8080/swagger-ui.html`
- OpenAPI JSON: `http://localhost:8080/v3/api-docs`

---

## 1. Entities & Relationships

```
Institution 1─N Department 1─N Program ├─N AccreditationCycle
                                        └─N AcademicYear 1─N Semester
```

| Entity | Owner | Stable ID exposed | Notes |
|---|---|---|---|
| Institution | this module | `institutionId` | code unique globally |
| Department | this module | `departmentId` | code unique per institution; `hodUserId` = external Keycloak ref |
| Program | this module | `programId` | code unique per department |
| AccreditationCycle | this module | `accreditationCycleId` | `tier` configurable, `frameworkVersion` free text |
| AcademicYear | this module | `academicYearId` | name unique per program |
| Semester | this module | `semesterId` | number unique per academic year |

All IDs are UUID (v4). They are generated by this module and are immutable.

## 2. Identifiers other modules should consume

| You are building | Depend on |
|---|---|
| Course module | `programId`, `academicYearId`, `semesterId` |
| SAR module | `accreditationCycleId`, `programId` |
| OBE / Outcomes | `programId` |
| Evidence | `programId`, `accreditationCycleId` |

The minimal program contract (`GET /api/v1/programs/{programId}`) always returns at least:

```json
{
  "id": "UUID",
  "name": "B.Tech Computer Science and Engineering",
  "code": "BTECH-CSE",
  "degree": "B.Tech",
  "branch": "Computer Science and Engineering",
  "departmentId": "UUID",
  "status": "ACTIVE"
}
```

Do **not** cache these IDs as anything other than opaque strings. Do not assume ordering.

## 3. Standard response envelopes

Success:
```json
{ "success": true, "data": { }, "message": "…", "timestamp": "2026-09-09T10:00:00Z" }
```
Error:
```json
{ "success": false,
  "error": { "code": "PROGRAM_CODE_ALREADY_EXISTS", "message": "…", "details": [] },
  "timestamp": "2026-09-09T10:00:00Z" }
```

List endpoints wrap results in a `PageResponse`:
```json
{ "content": [ ], "page": 0, "size": 20, "totalElements": 42, "totalPages": 3, "first": true, "last": false }
```

### Error codes (stable)
`VALIDATION_FAILED (422)`, `BAD_REQUEST (400)`, `UNAUTHORIZED (401)`, `FORBIDDEN (403)`,
`*_NOT_FOUND (404)`, `*_ALREADY_EXISTS (409)`, `ACTIVE_ACCREDITATION_CYCLE_EXISTS (409)`,
`INVALID_STATE_TRANSITION (409)`, `INVALID_DATE_RANGE (422)`,
`SEMESTER_DATES_OUT_OF_RANGE (422)`, `INTERNAL_ERROR (500)`.

## 5. Request DTOs (key fields)

**ProgramRequest**: `departmentId*`, `name*`, `code*`, `degree`, `branch`, `description`,
`durationYears*(>0)`, `totalSemesters*(>0)`, `intake*(>=0)`, `establishedYear`.

**DepartmentRequest**: `institutionId*`, `name*`, `code*`, `description`, `hodUserId`.

**AccreditationCycleRequest**: `name*`, `tier*`, `frameworkVersion*`, `applicationYear*`,
`startDate`, `endDate`, `remarks`. (`startDate < endDate`, tier in allowed set.)

**AcademicYearRequest**: `name*`, `startDate*`, `endDate*` (`startDate < endDate`, unique name/program).

**SemesterRequest**: `semesterNumber*(>0)`, `name*`, `startDate`, `endDate`
(dates must fall within the academic year; number unique per year).

`*` = required (backend-validated, not just frontend).

## 6. Status enums & lifecycle

- **Program**: `DRAFT → ACTIVE → INACTIVE → {ACTIVE, ARCHIVED}`.
- **AccreditationCycle**: `DRAFT → PREPARATION → SUBMITTED → UNDER_REVIEW → {ACCREDITED → EXPIRED | REJECTED → PREPARATION}`; `*→CANCELLED` from early states.
- **AcademicYear / Semester**: `PLANNED → ACTIVE → COMPLETED → ARCHIVED`.
- **Institution / Department**: `ACTIVE ⇄ INACTIVE`.

Invalid transitions return `409 INVALID_STATE_TRANSITION`. Historical accreditation data is
never physically deleted.

## 7. Authorization (Keycloak)

- Send `Authorization: Bearer <JWT>`.
- The module reads authorities from JWT claims: flat `permissions[]`, `realm_access.roles`,
  or `resource_access.<client>.roles`. Any of these matching a permission name grants access.
- Enforced at the API layer via `@PreAuthorize('hasAuthority(...)')` — hiding a UI button is
  never sufficient; the backend rejects unauthorized calls with `403`.
- Standalone dev: run with `APP_SECURITY_ENABLED=false` (a mock user with all permissions is
  injected; no Keycloak required).

See `docs/PERMISSIONS.md` for the full permission list and the RBAC integration contract.

## 8. Example calls

```bash
# Create a program
curl -X POST http://localhost:8080/api/v1/programs \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"departmentId":"<uuid>","name":"B.Tech CSE","code":"BTECH-CSE",
       "degree":"B.Tech","branch":"CSE","durationYears":4,"totalSemesters":8,"intake":120}'

# Fetch the integration contract (used by SAR/Course/OBE modules)
curl http://localhost:8080/api/v1/programs/<programId> -H "Authorization: Bearer $TOKEN"

# Program overview (dashboard with integration placeholders)
curl http://localhost:8080/api/v1/programs/<programId>/overview -H "Authorization: Bearer $TOKEN"
```

## 9. Data scoping seam (for the RBAC team)

The module calls a `DataScopeService` interface at read/write boundaries
(`assertInstitutionAccess/assertDepartmentAccess/assertProgramAccess/isReadOnly`). A
permissive default is provided for standalone dev. Provide your own bean implementing
`com.example.nba.security.DataScopeService` and it automatically replaces the default
(`@ConditionalOnMissingBean`) — no changes to domain services required.
